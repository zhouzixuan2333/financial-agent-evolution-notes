# 实验与数据口径索引

这页把五篇正文里的数字放回各自的实验。它保留可核对的历史结果，也说明哪些条件没有随公开材料提供。原始评测集、训练数据、日志和业务资料不进入仓库。

## 1. 不同证据能支持什么

| 类型 | 在本仓库中的用法 | 解释范围 |
| --- | --- | --- |
| 阶段结果记录 | 样本量、结果表、明确写出的 Runtime 和任务范围 | 能说明记录中的结果；缺少逐题导出时，不能重算或补出消融 |
| 训练实现复盘 | 数据格式、代表性配置、mask、token 对齐和部署流程 | 能解释训练机制；不能仅凭同为 4B 或 MoE 就绑定某个结果表 |
| 合成 Case / 伪代码 | 展示失败、状态变化、监督和评分边界 | 只解释方法，不属于实测效果 |

个人职责按本人完成的工作描述；模型成绩按实验记录描述。职责确认不替代实验条件，实验条件缺失也不等于没有做过该项工作。

## 2. 评测与检索阶段

| 编号 | 对象 | 已知条件 | 结果 | 解释边界 |
| --- | --- | --- | --- | --- |
| E1 | LLM Judge | 后续独立 100 条复测，与前期迭代样本不同 | 与人工一致率 93% | 一致率不等于取数准确率；未公开类别分布、混淆矩阵和逐题判定 |
| E2 | 新旧 Workflow | 1,385 条问句；严格、平均、最高三种历史口径 | 平均口径 61.48% → 79.32% | +17.84 个百分点；三种口径的完整判分函数没有公开 |
| E3 | 候选深度 | 当时 Workflow 的 TopK 敏感性实验 | Top40 / Top10 / Top5：78.81% / 79.32% / 79.10% | 没有明显候选深度收益；不能由此证明检索的普遍能力上限 |
| E4 | 目录树 Agent | 早期单项指标集合任务 | F1 71.31 → 91.68 | +20.37 个百分点；整体方案对比，不能拆给单项 Skill 修改 |

“最高口径”沿用结果源表的名称。仅凭它高于严格口径，不能把它定义成理论上界；也不能凭表中均值关系反推“平均口径”的逐题公式。

第一章中的季度/月度 Case 用来说明业务可计算性，不负责定义上述三个历史 scorer。

## 3. 训练实现线与成绩表分别对应什么

### 3.1 正文讲解的训练实现线

| 实验代号 | 模型与训练 | 输入 / 监督信号 | 在仓库中的位置 |
| --- | --- | --- | --- |
| T-SFT | MoE 全参数 SFT | 离线 Teacher 轨迹 / response-only CE | 第三章、第四章 SFT 部分 |
| T-LoRA | 大型 MoE，冻结 Base 做 LoRA RL | 在线 Session / 多 Skill 业务 reward | 第四章 RL 部分 |
| T-OPD | 4B Dense 学生，SFT 后在线蒸馏 | 学生 rollout / 教师 token logprob | 第四章 OPD 部分 |

SFT 实现资料中的“30B”是模型命名口径，训练统计约为 35B 级别。名称、总参数、可训练参数和每 token 激活参数是不同字段。第五章成绩表中的“35B”也是规模标签，仍需 checkpoint 才能将某轮训练与某次成绩一一对应。

### 3.2 多 Skill 阶段结果表

源表明确写出 **Claude Code SDK** 和六类金融任务：指标检索、结构化表格、新闻、公告、研报、专题报表。表中的模型标签是 SFT-4B、RL-4B、SFT-35B、RL-35B。

| 编号 | 模型规模标签 | SFT Average F1 | RL Average F1（源表标签） | 差值 |
| --- | --- | ---: | ---: | ---: |
| E5 | 4B | 63.28 | 67.97 | +4.69 个百分点 |
| E6 | 35B | 72.06 | 73.81 | +1.75 个百分点 |

这张表记录两种规模在该轮总览中的提升。公开材料没有提供 checkpoint、逐题分数、数据集 hash、Skill/Scorer 版本以及 Average F1 的完整聚合实现，因此保留源表结果，不将其扩写为可重算的公开 Benchmark。

尤其需要区分：

- **E5 的 RL-4B 不自动等于 T-OPD。** 同为 4B 无法证明两者是同一实验；不能把 67.97 直接写成 pure OPD 的业务验收分。
- **E6 的 RL-35B 不自动等于 T-LoRA。** 正文的大型 MoE LoRA 实验有独立基座与配置。
- **六类总览不等于七类 OPD 小评测或九类数据建设。** 任务集合不同，不能直接比较平均数。
- **Average F1 是源表名称。** 不同任务有不同主评分器，不能未经核对就宣称所有列都按同一 F1 公式计算，或自行假定宏平均权重。

## 4. 数据量分别在数什么

| 编号 | 数字 | 统计对象 | 与其他数据的关系 |
| --- | --- | --- | --- |
| D1 | 约 10,000 → 4,251 | 候选 QA 经执行与质量筛选后保留的 QA | QA 还需要 Teacher 执行才能成为轨迹 |
| D2 | 约 19% | 阶段材料中的标签不一致识别与修正比例 | 未明确分母与计算阶段，不能换算成确定的修正条数或准确率收益 |
| D3 | 约 6,400 | 多 Skill SFT 数据建设口径 | 结构化任务约 3,000、指标任务约 2,000、其他七类合计约 1,400；不等于任一训练运行的实际加载行数 |
| D4 | 约 7.9k | OPD 代表性配置中的任务题 | prompt 题库；不是 D3 直接追加得到的完整 Teacher 轨迹 |
| D5 | 70 题 | OPD 代表性小评测，七类各 10 题 | 适合诊断与回归，不能默认等同 E5/E6 的六类总览 |

一个问题经过多个 Teacher、Runtime 或 slash/nonslash 展开，可以产生多条训练行。QA 数、唯一问题数、Session 数、源轨迹行数、最终训练样本数和 optimizer step 都应分别记录。

数据处理资料记录了上游精确去重，也记录了 SFT 训练时按比例切 validation。这些信息本身不足以证明同源问题跨变体、跨阶段完全隔离。更严格的隔离方案与历史记录的区别见 [第三章](03-data-and-trajectory.md)。

## 5. 怎样比较准确性、稳定性和效率

我会把它们放在同一份结果里，避免只挑某一列：

| 视角 | 分母与条件 | 主要用途 |
| --- | --- | --- |
| 端到端任务表现 | 固定全部题目与尝试预算，明确失败计分和重试政策 | 判断系统实际能完成多少任务 |
| 执行状态 | 全量题目，按失败原因拆分 | 区分模型行为、Runtime、认证、网络与工具环境 |
| 条件业务质量 | 使用相同题目集合，列出覆盖率与排除原因 | 在可比执行条件下分析业务能力 |
| 效率 | 固定任务、质量目标、模型部署资源、并发、缓存和重试条件 | 比较耗时、Token、吞吐与成本 |

只统计各模型自己的成功样本，会得到不同分母；只比较单次生成速度，也不能代表多轮 Agent 的总耗时。端到端计时还包含 Skill 加载、工具等待和失败重试。

公开材料尚未提供足以重算的同口径性能记录，因此这里保留降低成本与延迟的工程目标，不公布缺少条件的百分比结论。

## 6. 后续实验记录应如何补齐

一条完整记录至少需要以下字段。它们是记录规范，不是声称历史实验已全部具备。

```text
实验标识：run_id、训练方式、base_model、checkpoint
协议：tokenizer、template、thinking、parser、Runtime
环境：Skill、工具环境、generation config
数据：数据集版本、同源分组方式、训练/调参/测试分工
统计：各任务题数、主 scorer、聚合公式、失败与重试政策
产物：逐题分数、执行状态、轨迹、耗时与 Token
```

更新一个数字时，应同时更新对应正文和这份索引。补证可以缩小解释边界，不能只换一个更高的分数而保留旧实验的名称与条件。
