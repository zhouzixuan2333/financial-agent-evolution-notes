# 项目地图：我做了什么，为什么这样做

这篇是五篇技术正文的入口。我想先把自己的工作串起来，再用一个合成 Case 说明：检索、Agent、数据和训练为什么会出现在同一个项目里。

## 0. 底层数据与目录结构

第一、二章主要围绕约 900 万级指标库取数，数据合成也会从其中选择可查询的指标。先看接口暴露的数据结构，才能理解后面的搜索、目录补找和标签校验。下面是重新编写的逻辑示意，不代表底层数据库的物理表设计。

### 一条指标怎样关联目录和数值

| 数据对象 | 包含的信息 | 用途 |
| --- | --- | --- |
| 指标记录 | 取数 ID、名称、地区、频率、单位、来源、可用时间范围 | 识别和选择指标 |
| 目录节点 | 所属模块、父节点 ID、节点下的子项 | 找到同一节点下的相关指标 |
| 时间序列 | 指标 ID，以及多条“日期—数值”记录 | 取回具体数据，进行计算 |

例如，一条指标记录可以这样理解：

```text
指标 ID：101
名称：某市工业产值：累计值
频率：季度；单位：万元；来源：某统计机构
可用时间：2020—2025 年
所属模块：M；父节点：P

按 ID 101 取数后：
2025-03-31 → 120
2025-06-30 → 260
```

这两个数分别是截至一季度、二季度末的年内累计值，不能当作两个单季值直接相加。名称中的统计口径，直接决定后续怎样使用数值。

父节点 P 下还可能有其他口径，而另一个父节点 Q 下也可能存在同名记录：

```text
数据模块 M
├── 父节点 P
│   ├── 101：某市工业产值：累计值
│   ├── 102：某市工业产值：累计同比
│   └── 103：某市工业产值：某细分行业：累计值
└── 父节点 Q
    └── 201：某市工业产值：累计值（同名的另一个指标 ID）
```

因此，搜索返回候选指标及父节点等信息；目录查询按“模块＋父节点”列出相关子项；取数再按选定的指标 ID 和日期范围返回数值。模型每次只接收这些局部结果。

### 接口返回中实际能观察到的问题

下面归纳的是历史轨迹中出现过的现象，图中的名称、ID 和数值均为示意。

| 观察到的结构现象 | 对使用方的影响 |
| --- | --- |
| 名称、频率、单位、来源和可用时间相同，却有不同 ID、不同父节点 | 名称不能唯一定位指标；按 ID 去重后仍可能保留业务含义相同的候选，但是否完全等价还要核对数值 |
| 同父节点下同时有累计值与累计同比，或供水单价与污水处理费 | 目录是相关项分组，不能把所有兄弟指标当作同口径答案 |
| 地区、行业、口径等信息经常嵌在名称里，排列顺序也不同，部分地区字段缺失 | 模型需要结合名称和元数据识别含义，不能只靠固定字段或关键词排名 |
| 搜索与目录展开使用不同的频率、来源字段名；有的取数结果有 ID 和数值，却没有指标名称 | 工具侧需要统一字段并保留已确认的 ID 对应关系，否则后续校验缺少信息 |

这里说的治理不足，具体表现为业务含义、指标 ID、目录入口和返回字段之间尚不能直接一一对应。多入口和混合目录本身可以有合理用途；字段差异、空名称也可能来自接口封装，不能据此断言底层数值错误。

### 为什么会影响检索和数据合成

检索时，TopK 可能被同名或近似指标占据；沿目录补找后还要检查口径。合成时，按目录组合出的目标也不一定适合直接比较，名称相同的不同 ID 更不能自动当作两个不同业务目标。需要确认指标含义、实际取回指定时间的数据，再据此构造问题和参考答案。

**底层目录与数据治理不在我们的改造范围内。** 我能控制的是候选判断、字段适配、缺项恢复，以及生成样本的执行校验。后续多 Skill 还涉及表格、新闻和研报等数据，不能把这里的指标库结构泛化成所有数据源的结构。

## 2. 为什么会走到下一个阶段

### 从快速检索到 Agent

第一阶段提高了常见问题的表现。Top5、Top10、Top40 的结果很接近，只能说明在当时的数据和方案下，继续增加候选深度没有明显收益，不能证明所有检索方法都到达上限。

决定引入 Agent 的另一半证据来自失败轨迹：问题要求“全部地区”，候选里却反复出现已找到的地区；某个路径为空后，系统缺少继续探索的动作。这里需要维护目标集合、观察工具返回并决定下一步。

### 从外部 Agent 到训练

强模型配合 Skill 先验证了任务可行性，也留下了成功与纠错轨迹。随后我需要把这些轨迹变成专用模型能够学习的行为，而不只是收集最终答案。

训练部分按 SFT → RL → OPD 讲述：先从固定示范学会基本执行，再用任务 reward 比较学生自己的多次尝试，随后引入教师对学生实际 token 的概率反馈。三者的监督信号逐步讲清，但各条实验使用不同模型，不是一条权重连续训练链。

## 3. 用一条合成问题贯穿整条链

> 以下地区、指标和值全部为解释机制而合成；这不是历史评测样本，也不参与仓库中的效果统计。

**问题：某城市甲、乙、丙三个地区在指定季度的工业用电量分别是多少，哪个地区最高？**

为便于说明，假设三个地区数据同单位、同统计范围，月度值可加，且无缺月或重复月份。

### 第一步：业务约束比语义相似更具体

一次平铺召回可能找到“全市工业用电量”。它命中了主题和城市，却没有覆盖三个地区。Judge 要检查的是地区集合、时间、单位和可计算关系。

### 第二步：Agent 维护覆盖状态

| 时刻 | 观察或动作 | 已覆盖 | 下一步 |
| --- | --- | --- | --- |
| 起点 | SEARCH_PATH 找到地区主题入口 | 空 | 展开目录 |
| 展开后 | 甲、乙有直接入口，丙在当前路径为空 | 空 | 记录三个待处理目标 |
| 首批取数 | 甲、乙的季度值返回 | 甲、乙 | 保留丙为缺项，检查关联路径 |
| 回退后 | 找到丙的三个月单月值 | 甲、乙 | 校验时间与口径后取回并求和 |
| 完成前 | 三个地区均有可解释结果 | 甲、乙、丙 | 检查覆盖、计算与最终答案 |

假设甲、乙季度值分别为 30、27，丙的三个月单月值为 9、10、12，则丙的季度值是 31，且为三者最高。甲、乙的取数互不依赖时可以同轮调用；丙的路径恢复需要先读取上一轮反馈。

无法找到某地区时，Agent 应说明已找到的结果和缺失项，并遵守探索预算。正确表达缺失与“完整回答了三个地区”是不同完成状态。

### 第三步：轨迹怎样成为训练数据

Teacher Session 保存搜索、取数、空结果、回退和最终回答。转换时保留原来的同轮调用组与错误上下文；不能因为最后答案正确，就随意删掉前面的失败动作。

进入 SFT 时，问题、工具说明和工具返回是条件；模型生成的调用与回答才是监督目标。是否训练非空 thinking 取决于模板与 mask，不能仅凭消息中出现了 `<think>` 就判断。

同源问题产生的不同 Teacher、Runtime 和 slash/nonslash 版本，应在数据隔离时视为同一组。历史数据建设与更严格的切分要求见 [第三章](03-data-and-trajectory.md)。

### 第四步：RL 与 OPD 怎样使用这道题

- **任务 RL**：同题采样多条 Session，比较实际任务 reward。若 reward 只匹配季度指标 ID，丙的月度求和路径可能被低估；需要明确 reward 的任务范围与等价规则。
- **OPD**：学生自己走轨迹，教师评价这些真实生成 token 的概率；教师不替学生重新跑一条正确路径。

这里暴露出两个监督目标的差别：模仿教师偏好的动作，和满足业务完成标准，不一定给出完全相同的反馈。

### 第五步：部署后仍要执行任务

即使模型会输出正确调用，如果 parser 不认识它的格式，工具也不会执行。验收要检查完整过程，而不是只检查服务能否返回文本。

## 4. 我会优先回看的四个问题

| 看到的现象 | 我先检查什么 | 不足以直接得出的结论 |
| --- | --- | --- |
| 扩大 TopK 没涨分 | 候选是否重复、正确目标是否出现、长尾是否缺覆盖 | 所有检索方案都无效 |
| SFT loss 下降但任务不提升 | 模板、调用合法性、训练数据与真实状态分布 | 模型一定需要更大规模 |
| RL reward 上升但离线分下降 | reward 能否解析当前输出、目标是否一致、数据和评测版本 | 某个训练机制一定导致退化 |
| 同一权重跨 Runtime 差距大 | Skill 加载、消息重渲染、调用映射、失败恢复 | 权重本身已经变差 |

这是我的复盘顺序，不是每种问题都已经完成因果消融的声明。具体成绩与可解释范围见 [实验与数据口径索引](06-experiment-index.md)。
